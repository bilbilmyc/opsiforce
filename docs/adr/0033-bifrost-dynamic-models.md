# Bifrost 管理动态渠道模型

Status: accepted (2026-09-14)

用户需要在 Bifrost 配置渠道后直接在 Opsiforce 选择模型。旧的镜像模型目录和硬编码虚拟 Key 渠道名单会产生不一致：项目 Key 创建失败，Agent 持续停留在启动中。

启用 Bifrost 的部署从 `/api/providers`、渠道 Key 元数据和 `/api/models/details` 生成可用聊天目录，保留准确渠道名及模型 ID。模型详情必须根据 `total` 和 `offset` 读取所有分页，不能将默认第一页当作完整目录。浏览器只接收名称，真实 Key 不出 Bifrost。Agent 统一通过 Bifrost 的 OpenAI Chat Completions 接口请求 `渠道/模型`。

项目启动前补齐缺失的 Bifrost 资源，更新已有虚拟 Key 的授权。每 30 秒及管理员手动刷新时同步目录、授权和共享工作区配置。OpenCode 监听配置文件并热加载目录；不重建镜像，不重启工作区。初始化容器接收同一目录，迁移保留动态配置。启用动态目录时禁用 models.dev 和旧内置供应商插件，避免固定目录混入选择器。

平台默认模型存于 `agent_model_defaults`，`can_manage_platform_defaults` 控制修改。已有对话的主动选择保留；删除默认模型时回退到可用目录首项。旧镜像配置仅保留给未启用 Bifrost 的独立部署。

当前目录只支持聊天、流式响应和工具调用。上下文、输入和输出规格优先取自 Bifrost 模型详情的有效正整数。无元数据的 GLM 5.3/Flash 按部署负责人提供的 1M 上下文配置，其他未知模型省略限制并继承 OpenCode 默认值（当前上下文 200K、输出预留 32K）。不再统一使用 32768/4096。输出预留用于压缩计算，不等同于请求的 `max_tokens`；此集成不额外设置后者。未核实规格不作官方声明。动态配置失败时返回错误或记录项目级同步失败，不能把读取目录成功当作推理成功。

替代 ADR 0008 和 0032 对 Bifrost 部署的限制。数据库迁移只新增默认设置表，不修改既有预算、用量或历史迁移。
